# Agent Resources (AR) topic evaluation — session note

Context: Mikhail proposed a new Agentic Stack direction/topic: AR = Agent Resources, useful once there are more than two agents. We ran Perplexity Sonar deep research with `search_sources=[social,web]` and synthesized the result for a management decision.

## Reusable decision pattern

For new Agentic Stack topic proposals, do not default to “create topic now.” Evaluate as a governance/routing decision:

1. Is this a durable class of work or just a temporary project?
2. Does it own execution, governance, or documentation?
3. Which existing topics already own adjacent work?
4. What thresholds justify a standalone topic?
5. What minimal artifacts can validate the need before creating topic sprawl?

## AR-specific conclusion

AR is a valid direction, but should start as a lightweight governance function rather than a heavy standalone topic while the active workforce is mostly Hermes/MM + Bud/OpenClaw.

Recommended trigger for standalone AR topic:

- more than 3–4 production agents;
- any non-core agent receives write access to critical/sensitive systems;
- recurring agent-specific incidents need cross-topic governance;
- AR artifacts are referenced weekly in real decisions.

Until then, keep AR as a section/artifact set inside an existing meta lane such as Perplex/Subconscious.

## AR scope

Owns:

- agent roster;
- roles/owners/status;
- capabilities, skills, tools, APIs;
- credentials, permissions, budgets;
- onboarding/offboarding/retirement;
- evals/performance;
- agent-specific incidents/postmortems;
- memory access policy;
- inter-agent conflict protocol.

Does not own:

- runtime repair/restarts/host ops — Server-doctor;
- human HR — HR;
- memory implementation internals — Subconscious;
- product/web execution — Web Admin;
- analytics implementation — Analyst;
- generic research — Perplex;
- day-to-day orchestration — Hermes/MM or workflow layer.

## Manager-style output shape that worked

Use concise Russian:

- verdict first;
- current recommendation;
- threshold for changing the recommendation;
- scope / non-scope;
- concrete policy text if useful;
- file paths only after the decision summary.

Avoid dumping the whole research unless asked. Link/save raw and synthesis artifacts separately.
