# Global Bud ACK before Hermes final — 2026-05-21

Session correction from Mikhail during Agentic Stack / Subconscious work.

## What went wrong

Hermes implemented Subconscious report/metric changes after Bud critique, then reported a final outcome to Mikhail. Bud had confirmed the general protocol later, but had not explicitly reviewed/accepted Hermes' concrete implementation summary.

Mikhail corrected two points:

1. Bud must confirm or challenge the concrete task outcome, not only the general protocol.
2. The Hermes → Bud → Hermes-before-final workflow applies across all Agentic Stack topics, not only Subconscious.

## Durable workflow rule

For Agentic Stack work where Bud/OpenClaw is expected to implement, review, or validate:

1. Hermes formulates the task in the relevant subject topic and tags `@iq5000_bot`.
2. Bud answers visibly before implementation or before final closure:
   - `ok`
   - `needs changes`
   - `cannot do`
   - `move this part to Server-doctor / another topic`
3. If Hermes already changed something before Bud ACK, label it as `post-factum review needed`, not as a completed MM↔Bud cycle.
4. Hermes gives Mikhail the final summary only after Bud has accepted/challenged the concrete task result, or Mikhail explicitly says to proceed without Bud.
5. Bud ACK is not a rubber stamp; Bud should identify weak points, risks, missing verification, or topic-boundary violations.

## Reporting language

Avoid saying:

- "Bud confirmed the protocol, so the task is closed."
- "Bud review exists" when Bud reviewed only the process, not the actual result.

Prefer:

- "Bud confirmed the protocol; concrete implementation still needs Bud post-factum review."
- "Status: implemented solo by Hermes; awaiting Bud acceptance/challenge before final closure."

## Scope

Applies to all Agentic Stack topics and subject workstreams. Subconscious was the incident, not the only scope.
