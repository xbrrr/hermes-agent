# X copywriting regression scenarios

Run with an isolated writer, then manually review meaning and voice. Do not test by posting to X. Style cannot be certified by word counts alone.

## Observed failures in earlier drafts

- Repeated "i'd" and symmetrical paragraphs sounded like an advisory article.
- Six pricing schemes displaced the intended services.
- A contract-approval service displaced token/DAO management and revenue curation.
- ETH fees, API prices, compute advances and token locks appeared without a basis.
- Cost waterfalls and repeated buyback calculations crowded out the deliverable.
- Editorial prefaces appeared when the request was for a final English post.

## A: meaning under detail pressure

Brief: four proposals: (1) token launches and token/DAO management; (2) custom structural research on third-party contracts/hooks using code, onchain data and paid sources, for traders/researchers/agents/projects; (3) recurring tailored monitoring/reports; (4) help projects build revenue models and take a very small share of actual collected revenue. One separate shared buyback rule. Premium+ allows a long post, and a reviewer asks for thoroughness.

Pass: preserve all four ideas in numbered action-first points. Distinguish research from monitoring, and management from curation. Explain work and why customers might pay. No added auditing, financing or holder-discount business. No claim that one API supplies every metric.

## B: numbers and uncertain facts

Brief: add useful rough numbers. No prices, API quotes or agreed buyback share are supplied. An old draft has a $200 monthly API bill, $39 subscriptions, ETH fees and a 50% allocation.

Pass: do not inherit those as facts. Use only useful, clearly illustrative figures. No mandatory number per sentence or point. Keep allocation as an agreed share unless asked to choose one. Verify a current API price only if materially needed; otherwise omit it.

## C: halve without meaning loss

Brief: halve a supplied long draft; return only one lowercase English post as a person addressing readers.

Pass: count original and final characters with a tool. Preserve all four ideas and the common rule; cut bookkeeping first. About half the supplied length is the target, not a fixed character count. No preface, code fence, thread or editorial notes.

## D: latest correction wins

Brief: old drafts charge for contract approval; the user replaces that with token/DAO management and asks for a live conversational voice.

Pass: use the corrected offer, not the old approval fee. No safety guarantees, repeated "i'd" or generic engagement bait. Any question relates to what readers would use.

## Review rubric

1. Meaning: every latest requested proposal survives.
2. Value: every point gives concrete work and why it may work.
3. Honesty: hypothetical figures/capabilities are not current facts.
4. Economy: no duplicate mechanics or procedural budgets.
5. Voice: personal and audience-facing, varied short sentences.
6. Delivery: one finished post, requested language/format/length, no publication.

Record actual observed violations. Do not claim an independent baseline failed if it passed. The earlier rejected drafts are direct failure evidence.
